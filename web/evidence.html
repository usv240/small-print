Built on AWS

A static site, a small anonymous API, and nothing else

The heavy work (face landmarks, distance, the test itself) runs in the visitor's browser. AWS delivers the site and the on-device model, and stores one small anonymous record per test. Everything is defined in code with the AWS CDK, in one stack in us-east-1.

At a glance

  • A static site and a small anonymous API. CloudFront and a private S3 bucket serve the site; API Gateway, three Lambda functions and DynamoDB store one record per test. One AWS CDK stack in us-east-1.
  • Video never leaves the device. The only upload is one JSON result under 4 KB. No IP addresses or user agents are stored or logged.
  • About US$0.59 per 1,000 screenings, about 99% of it CloudFront delivering the on-device model. The free tier covers about 150,000 screenings a month.
  • Least privilege, checked in code: one role per function, security headers on every response, and cdk-nag on every synth.
  • The coding agent is auditable: 205 CloudTrail events from its own IAM role, including a test write that was refused.

Architecture

The request path in words, step by step 6 steps

In words:

  1. The browser loads the site from CloudFront, which reads it from a private S3 bucket. That includes Google's MediaPipe face model (3.8 MB) and its WebAssembly runtime (2.4 MB, Brotli-compressed at build time from 11.8 MB), hosted by us rather than a third-party CDN.
  2. The camera feed is processed in the browser. No image is ever sent.
  3. At the result, the browser sends one small anonymous JSON record to /api/v1/results on the same origin. CloudFront forwards /api/* to an API Gateway HTTP API, which invokes a Lambda function that validates it and writes it to DynamoDB in a single transaction with the running totals.
  4. The impact page reads /api/v1/stats, which CloudFront caches for 30 seconds.
  5. Every 5 minutes, EventBridge runs an uptime Lambda that checks the home page, the health endpoint and the stats endpoint through CloudFront. CloudWatch holds the metrics, a dashboard and the alarms.
  6. At build time, Amazon Polly generates the voice-guide clips, and the AWS CDK deploys the whole stack after cdk-nag checks it.

Security and least privilege

Six safeguards: no personal data or images, no IP addresses, one role per function, security headers, abuse and cost limits, and the known limits 6 points
  • No personal data, no images. The API accepts only the fields listed on the privacy section; unknown fields are rejected and the stored item is rebuilt from validated values. Requests over 4 KB are rejected, which could not carry an image anyway.
  • No IP addresses or user agents are stored or logged. API access logs leave them out; function logs carry only validated values and error types; CloudFront and S3 access logs are off because they would record visitors' IP addresses.
  • Each function has its own role, with no AWS managed policies: it can write only to its own log group and use only the DynamoDB actions it needs, restricted to its own key prefixes (dynamodb:LeadingKeys). The uptime function has no data access at all.
  • Security headers on every response: HSTS, Permissions-Policy: camera=(self) (no microphone or location), X-Content-Type-Options: nosniff, X-Frame-Options: DENY, and a strict referrer policy.
  • Abuse and cost limits: throttling, strict validation, the size cap, edge caching of the stats, the budget, and the uptime and error alarms. A web application firewall (at least US$5 a month) did not fit the US$10 budget; that trade-off is recorded as an acknowledged cdk-nag finding.
  • Known limits: the API Gateway's own hostname is publicly reachable, bypassing CloudFront (throttling still applies); and the single running-total item per traffic type would need sharding above roughly 100 writes a second.

How the coding agent built it

Small Print was built with an AI coding agent, Claude Code, working with a human developer. (The app itself uses no AI to decide anything about your eyes.) The agent connected to AWS through the AWS MCP Server (Agent Toolkit for AWS) using a dedicated IAM role, small-print-agent, used for nothing else. The role has:

  • ReadOnlyAccess, to inspect resources, logs and metrics;
  • permission to use the CDK deployment roles, so every change to infrastructure goes through the CDK and CloudFormation rather than direct edits;
  • Amazon Polly, to generate the voice clips;
  • CloudFront invalidations, to publish new versions of the site.

Because the role is used only by the agent, CloudTrail records its calls separately from any human activity in the account. The table below lists real CloudTrail events from that role.
